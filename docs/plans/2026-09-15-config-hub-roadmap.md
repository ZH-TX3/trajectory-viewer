# Config Hub — 后续迭代方向

> 日期：2026-09-15
> 状态：方向记录（Profiles 已排期实现）
> 前置：`2026-09-14-config-hub-design.md`

## 现状（已完成）

Config Hub 已打通四类资源的管理闭环：

| 能力 | 状态 |
|------|------|
| Skills / Agents | `~/.agents/` 单一事实源 + 软链接分发、漂移检测与收编、可恢复删除 |
| MCP | 统一库 + 逐工具开关 + 合并写入（Claude JSON / Codex TOML / OpenCode JSON5）、真实握手连通性测试 |
| Prompts & config | 就地编辑（受管路径守卫）、JSON 格式化、点击用 VSCode 打开 |
| 工具配置根 | 每工具可覆盖配置目录，支持 `~` 展开，所有派生路径跟随 |
| 通用 | 资源批量开关、删除进回收站、会话备份复用 |

## 后续方向

按价值排序，分四层。

### 1. 规划层（最能改变工具性质）

- **配置档案 Profiles** — 把「哪些资源 × 哪些工具启用」存成命名档案，一键切换（如「前端」「写文档」「最小」）。当前只能逐个开关；这一步把工具从"管理配置项"升级为"管理环境"。**← 本次实现**
- **配置包导出 / 导入** — 整套终端配置打包带走（复用现有 backup 的 zip 逻辑），用于换机或留档。

### 2. 横向能力（成本低、日常高频）

- **搜索 / 筛选** — 资源数量增长后需要按名称搜索；目前只有工具筛选和「待收编」筛选。
- **健康总览** — 顶部汇总：失效软链接、配置文件语法错误（JSON/TOML/YAML）、漂移项、未安装工具，点击定位。
- **变更历史与撤销** — 删除已可恢复，但配置写入（MCP、prompt）直接落盘，没有回滚。

### 3. 补齐现有四类的深度

- **Prompts 真正统一** — 目前各工具各改各的；「共享基础 + 逐工具增量」的拼接模型在设计阶段被推迟，那才是共性管理。
- **Agents 扩面** — 目前仅 Claude；DSH 的 `.agent-presets/`、OpenCode 的 agent 尚未纳入。
- **MCP 预设库** — fetch / time / memory / context7 等一键添加；写入前预览各工具的实际落盘格式。
- **Skills 内容预览** — 目前只能链/删，看不到 `SKILL.md` 内容，启用前无法判断用途。

### 4. 更广的配置面

- `commands/`（斜杠命令）、`hooks`、`permissions`、`plugins`、keybindings —— 目前完全未覆盖。
- 工具版本与安装状态检测（CLI 是否在 PATH、版本号）。

## 建议顺序

1. **Profiles**（规划层，本次）
2. **搜索 + 健康总览**（横向能力，改善日常手感）
3. 按需：配置包导出、Prompts 统一、MCP 预设库
